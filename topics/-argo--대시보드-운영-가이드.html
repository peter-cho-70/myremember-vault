🎯 Argo 개요

핵심 특징

✅ 폴더 단위 기억
   - 대화, 산출물이 내 파일로 남아 소유
   - journal, notes, projects 폴더에 자동 저장

✅ 로컬퍼스트 + BYOK
   - 러너는 본인 계정으로 연결
   - 데이터는 내 볼트(회사/개인)에 저장

✅ 크루 구조
   - 챗봇이 아닌 에이전트 팀
   - 크루끼리 위임·회의 가능

✅ 자가학습
   - 스킬을 쓸수록 스스로 저장
   - 크루별로 학습 누적

✅ 안전장치
   - 발송, 삭제, 구매 등 중요 행동은 결재 필요
   - 파일 쓰기 같은 작업은 결재 없음 (설계 의도)

공식 웹사이트

https://argo.ceo

🔌 러너(Runner) 설정

러너 종류

1️⃣ Claude SDK 러너 (✅ 권장)

특징: - ✅ MCP 완벽 지원 - ✅ 10분 이상 장시간 작업 가능 - ✅ 대화 중단 없이 백그라운드 실행 - ✅ 결과는 대화/메신저로 배달

연결 방식: - API 키 사용 - OAuth 구독 로그인

권장 용도: - MCP 작업 전담 크루 - 장시간 작업 필요한 크루

2️⃣ Codex CLI 러너

특징: - ❌ MCP 미지원 - ⏰ 5분 타임아웃 (턴 한계) - ⚠️ 샌드박스 환경 (권한 제한)

알려진 문제: - 읽기/쓰기 권한이 제한적 - “read-only sandbox / rejected by user approval” 에러 - 이는 Argo 문제가 아닌 Codex CLI 샌드박스 자체 제한

권장: - Codex는 사용하되, 파일 작업은 SDK 러너에 위임 - 예: STS_총괄 PD는 Codex 유지, MCP는 SDK 크루에 맡기기

3️⃣ 기타 러너

✅ GLM (Google Gemini 모델)
✅ Kimi (Claude 호환)
✅ OpenRouter (멀티 모델)
✅ Grok (X의 LLM)
✅ Antigravity (5분 제한)

러너 연결 체크리스트

1️⃣ 크루 카드에서 러너가 실제로 지정되어 있나?
   └─ 크루 카드 열기 → 러너 확인

2️⃣ 설정 → AI 연결에서 검증됨 상태인가?
   └─ 로그인만 된 상태 ≠ 검증됨 상태
   └─ 검증이 안 끝나면 크루가 절반만 동작

3️⃣ 설정 → 능력 → 파일 시스템 토글 (회사 단위)
   └─ 끄면 어떤 러너도 쓰기 불가능

4️⃣ 버전 확인
   └─ 최신으로 업데이트되었는가?
   └─ npm/homebrew로 설치한 Codex는 버전 업데이트 필수

👥 크루(Crew) 관리

크루 설정 방법

1. 설정 화면에서 새로운 크루 영입
2. 러너 지정 (Claude SDK 권장)
3. 페르소나 설정 (프롬프트/지침)
4. 필요한 MCP 도구 연결

크루 작업 모니터링

CLI 러너 크루 (5분 제한):

- 응답이 5분 없으면 턴 끝남
- "턴 실패: 입력을 복원했습니다" 에러
  → 응답 없는 게 아니라 시간 한계에 걸렸을 가능성

SDK 러너 크루 (무제한):

- 10분 이상 작업 가능
- 대화 중단 없이 백그라운드 실행
- 끝나면 결과를 메시지로 배달

크루 구성 예시

[구성] 다양한 작업별 크루 팀

📌 STS_총괄 PD
├─ 러너: Codex CLI
├─ 역할: 문서/데이터 검토
└─ 특징: 기존 설정 유지

📌 MCP_담당 크루
├─ 러너: Claude SDK
├─ 역할: GitHub/외부 API 관리
├─ MCP 연결: modelcontextprotocol-server-github
└─ 특징: 파일 작업은 여기서 처리

📌 Data_분석 크루
├─ 러너: Claude SDK
├─ 역할: 데이터 분석/처리
└─ 특징: 10분 이상 작업 지원

답: (공식 명시 없음 - 웹소켓/실시간 통신 추정)

권한별 크루 배치 전략

[권한 수준별 크루 구성]

1️⃣ 완전 자동 (Bypass Permissions)
   ├─ 신뢰할 수 있는 작업만
   ├─ 설정: VS Code claudeCode.allowDangerouslySkipPermissions = true
   └─ 또는: Shift+Tab으로 bypassPermissions 모드 전환

2️⃣ 선택적 권한 (Default)
   ├─ 중요 행동만 결재 요청
   ├─ 발송, 삭제, 구매
   └─ 파일 쓰기는 자동 진행

3️⃣ 제한된 권한 (Sandbox)
   ├─ 특정 폴더만 접근
   ├─ 크루별/폴더별 권한 설정
   └─ Git을 활용한 권한 구분 권장

🔐 권한 관리

권한 설정 원칙

Argo의 설계 의도:

회사 안 작업 (파일 쓰기) → 결재 없음, 바로 진행
되돌리기 어려운 행동 → 결재 필요
  - 발송
  - 삭제
  - 구매

권한 관리 모범 사례

Git 활용:

폴더별로 권한을 나누면:
- 개발자들이 수십년간 연구한 방법
- 크루별 접근 범위 명확화
- 실수로 인한 피해 최소화

예시:
📁 /trusted/      → 완전 권한
📁 /restricted/   → 읽기만
📁 /workspace/    → 프로젝트별 쓰기

권한 위임 고민:

AI에게 권한을 얼마나 열어줄 것인가?
- 편함 vs 위험 트레이드오프
- 타입별 크루 분리로 해결
- 중요 작업은 검수 크루 거치기

Claude Code 권한 설정

폴더 제한 불가:

Claude Code는 폴더별 권한 제한이 없음
→ 로컬 컴 전체에 접근 가능 (현재 구조)

대안:
- bypassPermissions 켜고 신뢰 환경에서만 사용
- 또는 격리된 개발 환경에서만 실행

일반적인 문제 & 해결책

문제 1: Codex 크루에서 쓰기 권한 없음

증상:

Claude로 지시 → 파일 수정/이동 OK
Codex로 바꿈 → 쓰기 권한 없음 에러

원인:

Codex CLI의 샌드박스 제한
(read-only / workspace-write / full-access 모드)

해결책:

1. Codex 글로벌 폴더 열기
2. 진단 요청 ("이 문제 해결해달라")
3. 권한 설정 확인 (터미널 명령어)
4. 또는 파일 작업을 SDK 크루에 위임

문제 2: “턴 실패: 입력을 복원했습니다” 오류

증상:

Argo가 이 에러 메시지 표시

원인:

- 일시적 통신 문제 (대부분)
- CLI 러너 5분 제한 (자주)

해결책:

1. 어떤 러너(CLI vs SDK)인지 확인
2. API/OAuth 연결 방식 확인
3. 스크린샷 올려서 정확한 오류 파악
4. SDK 러너 사용으로 전환 (권장)

문제 3: 크루가 오래 응답이 없음

증상:

크루에게 작업 지시했는데 응답 없음

진단:

1️⃣ 어떤 러너인가?
   - CLI 러너 → 5분 후 자동 끝남 (실제 진행 아님)
   - SDK 러너 → 10분 이상 작업 후 배달

2️⃣ 각 러너별 특성 다름

문제 4: “검증됨” 상태 못 찾음

상황:

설정 → AI 연결에서 "검증됨" 표시 확인 불가

의미:

- 로그인만 되고 검증 미완료 상태
- 크루가 절반만 동작하는 원인이 될 수 있음
- 재인증 필요

문제 5: 다른 PC에서 로그인 안 됨

상황:

회사 PC와 집 PC 간 계정 동기화 오류
멀티 디바이스 동기화 문제

해결책:

Pro 버전 업그레이드
→ 다른 PC에서 자료 그대로 가져오기 가능

👤 페르소나 설정

페르소나란?

크루에게 정해진 성격·업무 방식을 자동 적용하는 설정

예시:
- 정보 분석가 페르소나
- 마케팅 전략가 페르소나
- 개발자 페르소나

페르소나 사전설정 도구

SoDam-Persona:

Claude Code용과 Codex용 버전 출시됨

특징:
✅ 15개 전문가 관점 검토
✅ 성격·업무 방식 자동 적용
✅ 설치 시 바로 활성화
✅ 커스텀 가능

설치:
깃허브 링크에서 다운로드
→ Argo에 페르소나로 등록

페르소나 만드는 방법

1. 기존 프롬프트/지침 있으면 그대로 붙여넣기 (빠름)
2. 또는 크루 카드에서 새 페르소나 작성
3. 크루가 작업하면서 자동으로 스킬 쌓임

🔗 MCP 연동

MCP란?

Model Context Protocol
- AI 에이전트가 외부 도구 사용 가능하게 해주는 표준
- Argo에 필요한 기능을 추가하는 방식

Argo의 MCP 지원 현황

❌ Codex CLI 러너
   → MCP 미지원
   → 추가 MCP 설치 안 됨

✅ Claude SDK 러너
   → MCP 완벽 지원
   → GitHub, 각종 도구 연동 가능

필수 MCP 도구 (권장)

GitHub MCP

도구명:

modelcontextprotocol-server-github

기능:

✅ 저장소 관리
✅ 이슈 추적
✅ PR 검토
✅ 리뷰 작성

설정:

1. SDK 러너 크루 1명 생성 (MCP 전담)
2. GitHub MCP 연결
3. 크루에 할당

MCP 설정 구조

설정 위치:

설정 → MCP 도구 → (각 도구별 연결 설정)

크루별 할당:

각 크루 카드에서 필요한 MCP 선택
→ 같은 러너라도 크루별로 다른 MCP 사용 가능

🔄 기타 주요 기능

볼트(Vault) 구조

Argo의 기억 저장소:

볼트별 폴더 구조 (회사/개인 단위)

📂 journal/
   └─ 대화 기록 자동 저장

📂 notes/
   └─ 노트 및 메모

📂 projects/
   └─ 산출물 (코드, 문서 등)

특징:

✅ 러너 바꿔도 기억 유지
   - 새 러너가 기존 파일 읽고 이어서 작업
   - Claude → Codex로 변경해도 컨텍스트 보존

✅ 소유권 명확
   - 모든 산출물이 내 폴더에 저장
   - 혼자서 정보 관리 가능

Dispatch (Claude 연구 프리뷰)

기능:

Claude Desktop과 연결하면:
- PC의 Claude와 하나의 대화 유지
- 휴대폰으로 지시 전송 가능
- 작업 결과는 나중에 확인

보안:

✅ 코드는 로컬 샌드박스에서 실행
✅ 파일은 외부로 나가지 않음
✅ 권한은 사용자 승인 후 진행

슬랙 연동

특징:

❌ 다른 도구의 슬랙 봇 토큰 자동 이전 불가
✅ Argo에서 새로 설정해야 함

설정 절차:
1. Argo 설정 → Slack
2. 워크스페이스 연결
3. 봇 토큰 재인증

📈 Argo의 진화 방향

진행 중인 기능 개발

✅ AI 멀티 오케스트레이션
   - 사용자 직접 설정 기능
   - 모델 추가 및 선택 기능 거의 완료

✅ 페르소나 관리 고도화
   - 새 페르소나 생성
   - 기존 설정 수정

✅ 대화 기반 설정
   - 100개 이상 대화 누적 시 새 세션 권장
   - 컨텍스트 윈도우 크기에 따라 조정

💡 운영 팁

팁 1: 대화 기록 관리

대화가 100개 이상 쌓일 때:
- 새 세션에서 진행 권장
- 컨텍스트 윈도우 효율 증가
- 비용 절감

팁 2: Pro 버전 필요성

Pro 업그레이드 필요한 경우:
✅ 멀티 디바이스 동기화 사용 시
   - 다른 PC에서 자료 그대로 가져오기

❌ 기타 기능은 무료 버전에서 사용 가능

팁 3: 크루 구성 최적화

추천 구조:
1. 일반 작업용 → Claude SDK 러너
2. 이전 설정 유지 → Codex CLI 러너 (읽기만)
3. 파일 작업 → SDK 러너에 위임 (속도·성능 향상)

팁 4: 권한 설정 원칙

편함과 안전의 균형:
- 신뢰할 수 있는 작업: 전체 권한
- 테스트·학습용: 선택적 권한

📞 자주 묻는 질문 (FAQ)

Q: 기존에 쓰던 에이전트·스킬을 Argo로 옮길 수 있나?

A: 완전 자동 이전은 불가능. 대신: - 크루 설정 시 기존 프롬프트/지침 붙여넣기 - 스킬은 크루가 작업하면서 자동으로 쌓임

Q: 러너를 중간에 바꾸면 이전 기억을 못 하나?

A: 반대. 볼트에 저장된 파일 덕분에: - journal, notes, projects는 그대로 유지 - 새 러너가 기존 파일 읽고 이어서 작업

Q: Codex 쓰면서 파일 작업을 하고 싶은데?

A: Codex는 샌드박스 제한 있음: - Codex는 검토용으로만 - 파일 작업은 Claude SDK 러너 크루에 위임 - 같은 폴더에 저장되므로 협업 가능

Q: 윈도우에서 쓸 수 없나?

A: 현재 macOS만 지원 중. 윈도우 지원 계획 확인 필요.

Q: Shift+Tab으로 bypassPermissions 켜면?

A: 권한 검사를 완전히 꺼버리는 것. - 신뢰할 수 있는 환경에서만 사용 - 보안 위험 높음
