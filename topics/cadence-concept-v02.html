CADENCE CONCEPT v0.2

업무의 90%가 지나가는 하나의 앱을 만들고 — 그 안에서 벌어진 행동을 자동으로 쌓아, 주간에는 습관을 관찰하고, 격주에는 프로세스를 실험하고, 월간에는 노하우로 응결시키는 개인 업무 운영체제.

허브

직접 만드는 전용 데스크톱 앱 (로컬 우선)

수집

자동 로깅 + 하루 3분 구조화 회고

범위

회사 업무 + 개인 프로젝트 (vMix / Tally / LED / 큐시트 등)

연계

기존 지식관리 시스템(MyRemember)의 /areas /topics에 출력

00한 문장 정의

CADENCE는 "내가 무엇을 했는가"를 기록하는 도구가 아니라, "내가 어떻게 일하는 사람인가"를 시간이 지날수록 더 정확하게 알아내는 기계다.

이 구분이 전체 설계를 지배합니다. 전자는 타임트래커고, 이미 세상에 100개쯤 있고, 3주 뒤에 안 씁니다. 후자는 관찰 → 가설 → 실험 → 승격이라는 루프가 돌아야만 성립하고, 그 루프가 이 문서의 핵심입니다.

이름 후보

CADENCE 리듬·박자. 주기가 핵심인 시스템 성격에 맞음 (본 문서 기본값) MyRhythm 기존 MyRemember(지식)와 짝 — 지식/행동 2축 LOOP 짧고 직관적. 피드백 루프 강조 Flywheel 누적 가속 은유. 다소 유행어

01왜 이런 시스템은 대부분 실패하는가

먼저 실패 지점을 못 박고 시작해야 설계가 그걸 피해갑니다. 관찰되는 실패 유형은 4가지입니다.

① 기록은 쌓이는데 아무 일도 안 일어남

리포트를 읽고 "오 그렇구나" 하고 닫음. 다음 주에 똑같은 리포트가 옴. → 방어책: 격주 제안은 반드시 "실험" 객체로 등록되고, 채택된 실험의 진행률이 주간 리포트에 강제로 박힌다.

② 입력 마찰로 3주 만에 사망

로깅이 귀찮아지는 순간 앱을 안 켬. 앱을 안 켜면 데이터가 끊기고 리포트가 무의미해짐. → 방어책: 수동 입력 총량을 하루 3분으로 하드 캡. 질문 4개 고정, 늘리지 않음.

③ 지표를 목표로 착각해 자기기만

"집중시간 지표"를 올리려고 의미 없이 앱을 켜둠. 데이터가 오염됨. → 방어책: 모든 숫자는 목표치 없이 표시. 점수·등급·연속기록(streak) 일절 없음.

④ 초반 3주가 시시해서 이탈

데이터가 없으니 리포트가 얄팍하고, 얄팍하니 안 씀. → 방어책: 콜드스타트 설계 — 1주차는 "리포트" 대신 "이번 주 발견 3개"만. 기대치를 명시적으로 낮춤.

024계층 데이터 피라미드

설계의 중심 아이디어는 이겁니다: 데이터 계층과 리포트 주기가 1:1로 대응한다. 주기를 임의로 정한 게 아니라, 각 계층이 의미를 가지려면 그만큼의 시간이 필요하기 때문에 정해진 겁니다.

월 1회 L3 — KNOWHOW 노하우 / 워크플로우

재사용 가능한 절차와 판단 기준. "Tally 배선 트러블슈팅은 이 순서로 한다"

격주 1회 L2 — PATTERN 행동 패턴

반복되는 경향과 마찰. "화요일 오후엔 40분 이상 세션이 한 번도 안 만들어진다"

주 1회 L1 — SESSION 작업 세션

이벤트를 묶은 의미 단위. "Tally 펌웨어 디버깅 47분, 중단 3회"

실시간 L0 — EVENT 원시 이벤트

앱이 자동으로 남기는 초/분 단위 흔적. 커밋, 파일저장, 세션 시작·전환, 앱 포커스

주기가 왜 1주 / 2주 / 1개월인가

  • 1주 — 근무 유형(R/L/U/W)이 최소 한 바퀴 도는 단위. 하루 단위는 노이즈, 한 달 단위는 유형별 차이가 뭉개짐.
  • 2주 — 비교가 성립하는 최소 단위. 주간 리포트 2개가 있어야 "지난주 대비"가 아니라 "경향"을 말할 수 있고, 각 근무 유형이 4~6회씩 표집되어 실험 판정에 필요한 최소 표본이 확보됨.
  • 1개월 — 같은 유형의 작업이 최소 2~3회 반복되어야 "절차"로 추출 가능. 방송기술 업무는 월/분기 주기 업무가 많아 특히 맞음.

04데이터 모델

로컬 SQLite 기준. 테이블 5개면 충분합니다.

설계 원칙 3개

  • L0는 append-only. 원시 이벤트는 절대 수정·삭제하지 않음. 나중에 분석 로직이 바뀌어도 과거를 다시 계산할 수 있어야 함.
  • 수동 입력은 reflection과 session의 nullable 컬럼에만. 안 채워도 시스템이 돌아가야 함.
  • knowhow.derived_from_json은 필수. "이 노하우가 어떤 실제 작업에서 나왔는지" 추적 안 되면, 6개월 뒤 그 문서를 믿을 수 없음.

05수집 전략 — 자동 90 : 수동 10

자동으로 잡는 것 마찰 0

  • 세션 시작/종료 — 앱에서 프로젝트 선택 후 시작 버튼 1회 (또는 유휴 감지로 자동 종료)
  • git 워처 — 지정 폴더의 커밋을 감시. 커밋 메시지 = 무료 작업 로그
  • 파일 저장 이벤트 — 작업 강도의 대리 지표
  • Claude Code / Cursor 세션 임포트 — 대화 로그에서 작업 주제 추출
  • 유휴 감지 — 5분 무입력 시 세션 자동 일시정지
  • 컨텍스트 스위치 — 프로젝트 전환 횟수 자동 집계

사람만 줄 수 있는 것 하루 3분

  • 왜 그 일이 오래 걸렸는가 — 자동으로는 절대 안 나옴
  • 마찰의 종류 — 대기? 정보부족? 도구? 사람? 내 집중?
  • 에너지 — 같은 60분도 질이 다름
  • 배운 것 — 월간 노하우 응결의 원재료

이 4가지가 없으면 리포트가 "당신은 이번 주 32시간 일했습니다" 수준에서 멈춥니다.

비개발 업무는 어떻게 잡는가

방송기술 업무 상당수는 커밋이 안 남습니다 — 장비 점검, 중계 대응, 회의, 큐시트 작업. 이건 앱에서 3탭으로 끝내는 퀵 로깅으로 처리합니다: [프로젝트] → [활동유형] → 시작. 종료는 유휴 감지 또는 다음 세션 시작 시 자동. 평균 입력 시간 5초 이하가 목표선입니다.

교대 근무 보정 — 이 시스템의 최대 변수

보도기술부 근무는 R(12:30–19:30) / L(06:00–16:00) / U(15:30–24:00) / W(00:00–07:30) 교대입니다. 이 사실 하나가 일반적인 행동분석 도구의 전제를 전부 무너뜨립니다.

  • "요일별 리듬"은 의미가 없습니다. 이번 주 수요일은 W(심야), 다음 주 수요일은 L(새벽출근)일 수 있습니다. 요일 축으로 집계하면 근무 유형이 섞여 노이즈만 남습니다.
  • "오전 9–11시가 몰입대"도 성립하지 않습니다. W 근무 중 오전 9시는 퇴근 후이고, L 근무 중 오전 9시는 근무 3시간째입니다.
  • "하루"의 경계가 흔들립니다. U 근무는 자정을 넘고, W 근무는 자정에 시작합니다. 날짜 기준으로 세션을 자르면 한 번의 근무가 두 날로 쪼개집니다.

대응 설계 3가지

일반 도구의 축 CADENCE의 축 이유
요일 (월~일) 근무 유형 (R/L/U/W/OFF) 같은 유형끼리 묶어야 비교가 성립. 월 5~6회씩 반복되므로 표본도 충분
시계 시각 (09:00, 14:00…) 근무 경과시간 (근무 시작 후 N분) "근무 2시간째가 가장 집중된다"는 유형을 넘어 일반화되는 발견
날짜 (00:00 기준) 근무 블록 (shift block) U 근무 22:00~01:00 세션이 하나로 유지됨. 회고도 근무 종료 시점 기준

부수 효과 — 이게 오히려 이 시스템의 킬러 기능이 됩니다. 교대 근무자는 "나는 어느 근무에서 어떤 일을 해야 손해가 없는가"를 감으로만 알고 있습니다. 6개월치 데이터가 쌓이면 "설계 작업은 L 근무 초반 3시간에 몰아야 하고, W 근무에는 문서·정리만 넣는다" 같은 결론이 숫자로 나옵니다. 일반 직장인용 생산성 도구가 절대 줄 수 없는 답입니다.

회고 알림도 시각 고정(예: 저녁 9시)이 아니라 근무 종료 시각 기준으로 걸어야 합니다. W 근무 퇴근은 오전 7:30이고, 그때 저녁 9시 알림을 기다리면 기억이 이미 날아갑니다. 근무 일정 데이터(캘린더)를 앱이 읽어와야 하는 이유이기도 합니다.

이 루프가 만드는 것

  • 제안이 추적되므로 무시할 수 없음
  • 실패한 실험도 기록 → 같은 제안이 재생성되는 것을 방지
  • 성공한 실험만 노하우가 됨 → 노하우 문서의 신뢰도가 근거로 뒷받침됨
  • 6개월 뒤 "내가 시도한 것 12개 중 성공 5개" 라는 자기 이해가 남음

안전장치

  • 동시 진행 실험은 최대 2개. 3개 이상이면 무엇이 효과를 냈는지 구분 불가
  • 채택하지 않은 제안은 dropped로 남기고 같은 제안을 60일간 재생성 금지
  • 2주 안에 측정 불가능한 제안은 애초에 생성하지 않음 ("커뮤니케이션을 개선한다" 같은 것)

11앱 구조 — 화면 4개면 충분

① NOW — 기본 화면

현재 세션 타이머 + 프로젝트/활동 선택 + 시작·전환·종료 버튼. 하루 중 99%의 시간 동안 이 화면만 떠 있음. 3탭 안에 세션이 시작되어야 함.

② TODAY — 하루 끝

오늘 세션 타임라인 + 회고 질문 4개. 저녁 시간에 알림 1회. 3분 안에 닫힐 수 있어야 함.

③ REPORTS — 읽기 전용

주간/격주/월간 리포트 아카이브. 격주 리포트에서만 [채택] 버튼이 동작.

④ VAULT — 축적물

누적된 노하우·규칙·실험 이력. MyRemember 저장소와 동기화 상태 표시. 이 화면이 시간이 갈수록 두꺼워지는 게 이 시스템의 보상 구조.

화면을 4개로 묶는 이유

설정·통계·대시보드·프로젝트관리 화면을 추가하고 싶어지는 순간이 반드시 옵니다. 그때 판단 기준: "이 화면 없이 주간/격주/월간 리포트가 나오는가?" 나온다면 만들지 않습니다. 이 앱의 목적은 사용하는 게 아니라 지나가는 것입니다.

13단계별 로드맵 — 앱부터 만들지 않습니다

가장 중요한 조언: Phase 0을 건너뛰지 마세요. 전용 앱을 먼저 만들면, 2주 뒤에 "내가 이 데이터를 실제로 안 남긴다"는 사실을 알게 되고 앱이 버려집니다. Phase 0의 목적은 기능 검증이 아니라 나 자신의 습관 검증입니다.

단계 기간 만드는 것 통과 조건
Phase 0
검증		 1주 앱 없음. 마크다운 파일 1개 + 회고 질문 4개를 손으로 채움. 세션은 간단한 CLI 한 줄 7일 중 5일 이상 회고를 채웠는가. 못 채웠으면 질문을 더 줄이거나 이 컨셉 자체를 재검토
Phase 1
수집		 2~3주 Tauri 앱 셸 + NOW/TODAY 화면 + SQLite. 세션 타이머, 유휴 감지, 회고 입력 2주간 데이터가 끊김 없이 쌓이고, 세션 시작 평균 소요 5초 이하
Phase 2
관찰		 2주 주간 리포트 생성기. SQL 집계 + LLM 서술 문단. MD/HTML 출력 첫 리포트에서 내가 몰랐던 사실이 1개 이상 나오는가
Phase 3
개입		 2주 격주 제안 엔진 + experiment 테이블 + 채택 UI + 주간 리포트에 실험 블록 삽입 제안 1개를 실제로 채택해서 2주 돌리고 판정까지 완주
Phase 4
축적		 2주 월간 응결 엔진 + VAULT 화면 + MyRemember 저장소 export 월간 초안 4종이 생성되고, 그 중 2개 이상을 실제로 저장소에 커밋할 만하다고 판단
Phase 5
확장		 이후 git 워처, Claude Code 세션 임포트, 비개발 업무 퀵로깅 개선 자동 수집 비중이 전체 이벤트의 70% 이상

총 9~11주. 다만 Phase 2가 끝나는 시점(약 5~6주)에 이미 매주 리포트를 받고 있으므로, 그 뒤로는 시스템을 쓰면서 만드는 구조입니다.

모바일 앱 보류 Phase 5 이후. 회고 입력만 웹으로 여는 정도
업무 외 일상 데이터 확장 보류 업무+개인 프로젝트로 6개월 돌린 뒤 재검토

가장 큰 리스크 — 개인정보와 회사 데이터

세션 노트와 회고에 회사 업무 내용이 들어갑니다. LLM 호출 시 프로젝트명·활동유형·시간·마찰태그 같은 메타데이터만 보내고, 자유 서술 텍스트는 보내지 않는 모드를 기본값으로 두는 것을 권합니다. 월간 문서 생성 때만 선택적으로 서술 텍스트를 포함하고, 그것도 로컬 모델로 대체 가능하게 설계해두면 안전합니다.

15다음에 결정할 것

지금 정해야 할 것

  1. 프로젝트 분류 체계 — 회사 업무를 몇 개 버킷으로 나눌지 (5~8개 권장). 이게 모든 집계의 축
  2. 활동 유형 목록 — 설계/구현/디버깅/조사/문서/회의/대응 이 7개면 충분한지
  3. 마찰 태그 목록 — 6개 제안했는데 실제 업무에 맞는지
  4. 회고 알림 기준 — 근무 종료 시각 기준으로 걸 것 (W 근무 퇴근은 오전 7:30). 근무 일정을 앱이 어디서 읽을지 — 캘린더 연동인지 수동 입력인지
  5. OFF일 처리 — 비번일의 개인 프로젝트 세션을 근무일과 같은 축에서 볼지, shift_type=OFF로 분리 집계할지

Phase 0 준비물 (이번 주 시작 가능)

  • 회고 템플릿 마크다운 1개
  • 세션 기록용 CSV 또는 한 줄짜리 CLI 스크립트
  • 저녁 알림 1개 (휴대폰 알람이면 충분)
  • 7일 뒤 자가 점검: 며칠 채웠는가

이 컨셉의 최종 그림

1년 뒤, VAULT 화면에는 워크플로우 문서 10~15개, 개인 규칙 8~12개, 완주한 실험 20여 개가 쌓여 있습니다. 새로운 방송 시스템 프로젝트를 시작할 때 "비슷한 작업을 언제 했고, 그때 무슨 순서로 했고, 어디서 막혔는지"가 검색 한 번으로 나옵니다. 그게 이 시스템이 만드는 최종 산출물입니다 — 리포트가 아니라, 시간이 지날수록 두꺼워지는 나의 작동 설명서.
