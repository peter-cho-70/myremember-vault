1. 전체 구성도

소스가 여러 개(하드웨어 스위처 · vMix · 큐시트)이므로, 핵심은 “어떤 소스가 붙어도 코어는 한 가지 형태의 이벤트만 안다”는 정규화 계층입니다. 이 한 가지 설계가 이후 확장성의 90%를 결정합니다.

1-3. 지연 예산 (Latency Budget)

구간 목표 비고
스위처 이벤트 → 어댑터 수신 ≤ 10 ms vMix API를 폴링으로 쓰면 여기서 수십 ms 손해 — 이벤트/구독 방식 우선

End-to-End ≤ 50 ms 허용 한계 100 ms · 파일럿에서 반드시 실측

💡 먼저 합의할 질문: 탈리가 1프레임(약 33ms) 단위로 맞아야 하는가?
온에어 램프는 프레임 정확도가 중요하고, UMD 문자 정보는 100ms여도 실무상 문제가 없습니다. 이 둘을 분리해서 설계하는 것이 이번 재설계의 가장 중요한 판단입니다.

2. 무엇부터 만들 것인가

결론: 하드웨어가 아니라 “상태 모델 → 코어 → 가상 단말” 순서입니다.
탈리 재설계에서 가장 흔한 실패는 단말부터 만드는 것입니다. 단말은 부품 수급·시제품·설치 리드타임이 길고 한 번 정하면 되돌리기 비쌉니다. 반면 코어와 프로토콜은 하루에도 몇 번씩 고칠 수 있습니다. 바꾸기 싼 것부터 확정하고, 바꾸기 비싼 것을 마지막에 정하는 순서가 맞습니다.

Phase 0

규격 확정

탈리 상태 모델, 정규화 이벤트 스키마, 단말 프로토콜 스펙, ID 체계를 문서 한 장으로 못박습니다.

산출물: 규격서 10p · 기간 1~2주 · 이후 모든 작업이 이 문서를 참조합니다. 여기가 애매하면 전부 흔들립니다.

Phase 1

Tally Core + 스위처 시뮬레이터

어댑터 1개(TSL) + 상태 엔진 + 매핑 테이블. 동시에 가짜 스위처를 만들어 둡니다.

기간 3~4주 · 실장비 없이 개발 가능해지고, 야간·주말에도 회귀 테스트가 돌아갑니다

Phase 2

가상 단말 (웹)

브라우저에서 PGM/PVW를 표시. 부조 스위처에 노트북 하나 물려서 하루만 돌려봅니다.

투자 0원으로 전체 체인 검증. 매핑 오류·우선순위 충돌·라벨 규칙 문제가 여기서 거의 다 드러납니다

Phase 3

단말 프로토타입 1~2대

ESP32-S3 + LCD + PoE. 밝기·시야각·지연·카메라 촬영 테스트.

기간 3~4주 · LCD 채택 여부의 실측 근거를 여기서 확보 (3-6 체크리스트)

Phase 4

웹 관리 콘솔

매핑 편성, 프로그램별 프리셋, 단말 헬스맵, 로그 조회.

기간 3~4주 · 운용 담당이 개발자 없이 직접 바꿀 수 있어야 시스템이 삽니다

Phase 5

파일럿 8~16대 설치 + 이중화 검증

코어 다운, 스위치 다운, 케이블 절단 — 장애 시나리오를 실제로 재현합니다.

기간 4~6주 · 기존 시스템 병행 운용 유지

Phase 6

확장

vMix 어댑터, 큐시트/MASTER 연동, RS-422 게이트웨이, 타 스튜디오 전개.

코어가 안정된 뒤에 붙여야 합니다

지금 당장 착수한다면, 이 3가지

① 탈리 상태 모델 정의 (반나절 회의)

  • 상태 종류: PGM / PVW / ISO / REC / CALL / IDLE / FAULT — 몇 개까지?
  • 동시 상태 우선순위 — PGM이면서 CALL이면 무엇을 보여줄 것인가?
  • 카메라맨용 / 출연자용 표시가 달라야 하는가?

② 정규화 이벤트 스키마 확정

{ "src": "switcher-a", "input": 3, "camera_id": "CAM3", "state": ["PGM"], "label": "3번 카메라", "seq": 1024, "ts": 1755100000123 }

③ 가상 단말로 하루 실증

부조 스위처 TSL 출력에 노트북 한 대 물려서, 웹페이지가 PGM을 제대로 따라오는지만 확인합니다. 이 하루가 이후 6개월의 방향을 정합니다.

⚠ 하지 말아야 할 것 — 처음부터 전 스튜디오 표준으로 설계하기 · 단말 외형·금형부터 확정하기 · 기존 RS-422를 즉시 철거하기.
롤백 경로(기존 시스템 병행)를 파일럿 종료까지 반드시 유지하세요.

3. 단말 표시장치 — LCD vs 도트매트릭스

3-1. 한눈에 보기

비교 축 도트매트릭스 (현행) LCD (IPS TFT) 유리한 쪽
시야각 사실상 전방위. 각도에 따른 밝기 저하가 적음 IPS라도 극단 각도에서 명암비·색 저하 도트매트릭스
휘도 매우 높음. 조명 아래·야외에서도 판독 일반 패널 200~500 nit, 고휘도는 단가 급증 도트매트릭스
응답 속도 사실상 즉시 패널 응답 + 프레임버퍼 갱신 → 수십 ms 추가 도트매트릭스
표현 정보량 영문·숫자 위주. 한글은 16×16 이상 필요 한글·다국어·아이콘·컬러 자유. 큐 정보·타이머까지 LCD
상태 구분 색 LED 조합으로 제한적 전체 화면 색면 + 문자 → 상태 종류 무제한 LCD
기능 확장 표시 방식을 바꾸려면 하드웨어를 손대야 함 레이아웃이 소프트웨어 → OTA로 기능 추가 LCD
수명 · 고장률 구조 단순, LED 수명 장대 백라이트 열화, FPC 커넥터 등 고장 포인트 증가 도트매트릭스
온도 내성 저온·고온 모두 안정적 저온에서 응답 저하, 고온에서 흑화 — 야외 중계 취약 도트매트릭스
글레어(반사) 반사면이 적음 유리 표면 반사 → AG 코팅 필수 도트매트릭스
촬영 플리커 LED 스캔 구동 시 밴딩 발생 가능 백라이트 PWM 디밍 시 플리커 발생 가능 둘 다 주의
단가 낮음 3~5배 (패널 + SoC + 메모리) 도트매트릭스
소비전력 낮음 높음(백라이트) — 단, PoE로 충분히 커버 가능 도트매트릭스
개발 난이도 낮음 (펌웨어 단순) 높음 (그래픽 스택 · 폰트 · 렌더링 · OTA) 도트매트릭스

3-2. LCD의 진짜 가치 — “정보 단말”로의 격상

LCD 전환의 의미는 “예쁜 탈리”가 아닙니다. 탈리 단말이 카메라맨을 향한 정보 채널이 된다는 것입니다. 큐시트/MASTER 연동을 함께 가져가시기로 한 이상, LCD가 열어주는 화면은 이런 모습입니다.

도트매트릭스로는 이 중 첫 줄밖에 못 합니다. 뒤집어 말하면 — 큐시트 연동을 하지 않을 거라면 LCD의 가치는 절반 이하로 떨어집니다. LCD 채택의 정당성은 화질이 아니라 연동 계획에서 나옵니다.

3-3. LCD의 진짜 리스크 — 세 가지

① 시야각 · 휘도

카메라맨은 단말을 정면에서만 보지 않습니다. 옆에서, 아래에서, 어깨 너머로 봅니다. 스튜디오 조명(수천 lux)이 화면에 직격하는 각도도 생깁니다.
→ 최소 500 nit, 가능하면 800~1000 nit + AG 코팅 + 조도센서 자동 밝기

② 지연

스위칭 순간과 탈리 점등이 1~2프레임 어긋나면 카메라맨은 “탈리가 늦다”고 체감합니다. 한 번 그런 인상이 생기면 시스템 신뢰가 무너집니다.
→ 파일럿에서 스위처 화면과 단말을 한 프레임에 담아 촬영해 실측

③ 촬영 시 플리커

방송 카메라에 단말이 잡히는 경우, 백라이트 PWM 디밍 주파수가 셔터와 간섭해 밴딩이 생깁니다.
→ DC 디밍 또는 고주파 PWM(20kHz 이상) 구동 패널 선정

3-4. 권장안 — 하이브리드 (역할 분리)

하나의 단말이 두 가지 일을 억지로 하게 하지 말고, “상태 표시”와 “정보 표시”를 물리적으로 나누는 것을 권합니다.

용도 대상 권장 방식 이유
온에어 상태 표시 출연자 · 원거리 시인 고휘도 LED 색면 패널
(도트매트릭스 계열 유지)		 시야각 · 휘도 · 즉시성이 절대 우선. 정보량은 불필요
카메라맨 정보 단말 카메라맨 근거리 LCD + 테두리 RGB LED 한글 · 큐 정보 표시 + 테두리 LED가 시야각/즉시성을 보완

테두리 RGB LED 조합이 핵심 아이디어입니다. 상태(PGM/PVW)는 화면 바깥 테두리 LED가 즉시·광시야각으로 알리고, LCD는 문자 정보만 담당합니다. 이렇게 하면 LCD의 두 약점(시야각·지연)이 상태 전달 경로에서 아예 빠지므로, 채택 리스크가 크게 줄어듭니다.

3-5. LCD 채택 시 권장 스펙

항목 권장
패널 2.4~3.5인치 IPS TFT, 해상도 320×240 이상
휘도 500 nit 이상 (권장 800~1000), AG 코팅
디밍 DC 디밍 또는 PWM 20kHz 이상 (카메라 플리커 방지)
인터페이스 병렬 RGB 또는 고속 SPI — 저속 SPI는 화면 갱신 지연의 주범
MCU ESP32-S3 (PSRAM 탑재) — 프레임버퍼 여유 + OTA
급전 PoE Splitter 또는 PoE 모듈, 단말당 5~8W
부가 조도센서(자동 밝기) · 테두리 RGB LED · 온도센서
하우징 회전/틸트 마운트 — 시야각 약점을 설치 자유도로 보완
펌웨어 Last-Known-Good 유지 + 링크 끊김 시 명시적 “LINK LOST” 표시

3-6. 파일럿에서 반드시 측정할 것 (채택 판단 기준)

  • 스튜디오 조명 직격 각도에서 3m 거리 판독이 가능한가
  • 좌우 60°, 상하 40°에서 상태 색이 명확히 구분되는가
  • 스위칭 → 표시 지연 실측 (목표 50ms, 허용 100ms)
  • 방송 카메라로 단말을 촬영했을 때 밴딩·플리커가 없는가
  • 8시간 연속 운용 시 표면 온도 및 밝기 변화
  • 카메라맨 5명 이상의 주관 평가 — 현행 도트매트릭스 대비

📖 용어집

용어 설명
탈리 (Tally) 어느 카메라가 지금 방송에 나가는지(PGM), 다음 예비인지(PVW)를 카메라맨·출연자에게 알려주는 신호 및 표시 장치
PGM / PVW Program(현재 송출) / Preview(다음 예비)
UMD Under Monitor Display. 모니터 하단에 소스 이름을 표시하는 장치. 탈리 상태를 함께 표시하는 경우가 많음
TSL UMD 프로토콜 영국 TSL사가 만든 탈리/UMD 표준 통신 규격. V3.1(시리얼 기반)과 V5.0(이더넷/UDP 기반)이 널리 쓰임
GPI / GPO General Purpose Input/Output. 단순 접점 신호로 상태를 주고받는 방식
RS-422 차동 신호 방식의 시리얼 통신 규격. 장거리·노이즈에 강해 방송장비에서 오래 사용
PoE / PoE+ Power over Ethernet. 랜선 하나로 데이터와 전원을 함께 공급. PoE+는 포트당 최대 약 25.5W
IGMP Snooping 스위치가 멀티캐스트 트래픽을 필요한 포트에만 보내도록 하는 기능. 켜지 않으면 네트워크 전체로 방송됨
멀티캐스트 하나의 송신으로 여러 수신자에게 동시 전달하는 통신 방식. 단말이 많을수록 유리
Last-Known-Good 통신이 끊겨도 마지막 정상 상태를 유지하는 설계. 탈리가 갑자기 꺼지는 것보다 안전
nit (칸델라/m²) 화면 밝기 단위. 실내 모니터 250~350, 야외 시인용 1000 이상
PWM 디밍 백라이트를 빠르게 켜고 꺼서 밝기를 조절하는 방식. 주파수가 낮으면 카메라에 줄무늬(밴딩)로 잡힘
AG 코팅 Anti-Glare. 화면 표면 반사를 줄이는 처리
IPS 패널 LCD 패널 방식 중 시야각과 색 재현이 좋은 편에 속하는 구조
OTA Over-The-Air. 단말을 분해하지 않고 네트워크로 펌웨어를 갱신하는 것
ESP32-S3 무선·USB를 갖춘 저가 마이크로컨트롤러. 화면 구동과 네트워크 처리를 함께 수행 가능
디바운스 신호가 짧게 떨릴 때 이를 무시해 표시가 깜빡이지 않도록 하는 처리
